# PRD-04：多前置综合挑战关

## 文档状态

- 状态：Draft
- 优先级：P1
- 依赖：PRD-02 能力状态、PRD-03 结构化直接操作
- 后续依赖方：PRD-05 补强回路

## 1. 背景与问题

严格的线性学习路径会迫使已经具备能力的学生重复学习；完全开放又无法提供清晰的推荐顺序。部分综合题同时依赖多个专题能力，适合成为图谱中的挑战节点：

- 学生可以提前尝试，用真实解题过程证明能力。
- 成功后可以跳过已被验证的重复内容。
- 失败后能够暴露具体缺失能力，而不是只得到一个分数。

## 2. 产品目标

- 支持一个挑战节点依赖多个 capability。
- 挑战关使用软门槛：即使前置未全部掌握，也允许主动尝试。
- 挑战成功必须依据完整动作证据，而非最终答案。
- 挑战失败不惩罚普通进度，并为 PRD-05 生成诊断入口。

## 3. 挑战类型

首版建议配置两类：

### 挑战 A：辅助线综合

依赖：

- 作平行辅助线。
- 迁移两组份数。
- 配对应边。
- 按份数列式。

### 挑战 B：构型混合辨认

依赖：

- 反 A 点序。
- 子母型共线边互化。
- 蝶形交叉点序。
- 对应边列式。

首版挑战节点数量应少于普通专题节点，避免地图被支线淹没。

## 4. 入口状态

挑战节点始终可点击，并与普通知识点使用同一套学生可见状态：

- `unopened` / 未开启：尚未尝试挑战。
- `open` / 开启：已经尝试但尚未通过，或存在未完成 challenge session。
- `passed` / 通关：挑战已通过。

“推荐前置均掌握”或“仍建议补前置”是详情信息，不是第四种节点状态。建议前置不足时显示：

```text
这道挑战建议先掌握：
✓ 平行线比例
△ 比例辅助线
△ 反 A 形对应边

[先补前置] [直接挑战]
```

不得用恐吓性文案阻止尝试，也不得隐藏直接挑战入口。

## 5. 挑战 session

挑战使用独立 session 类型，但继续复用统一 runtime：

```ts
type SessionKind = "practice" | "challenge" | "remediation";
```

挑战 session 必须记录：

- `challengeId`
- 目标 capability 列表
- 每个 capability 对应的动作证据
- 失败 `stepId` 与 `diagnosisCode`
- 是否为提前挑战
- 是否存在后续 remediation session

## 6. 通过规则

挑战通过需要：

- 完成全部核心步骤。
- 核心动作来自学生的结构化操作。
- 最终答案正确。
- 没有跳过被挑战关声明为必需证据的步骤。

只提交正确最终答案不得触发跳关。

通过后：

- 将挑战实际验证的 capability 写入 PRD-02 的证据系统。
- 重新计算图谱节点状态与推荐结果。
- 显示“已验证哪些能力”，而不是笼统显示“跳过 2 关”。

## 7. 失败规则

- 失败不降低已经掌握的能力。
- 失败后挑战节点保持开启，不退回未开启，也不产生锁定状态。
- 系统记录最早的核心阻塞动作和重复错误动作。
- 学生可以立即重试，也可以进入 PRD-05 的补强回路。

## 8. 挑战内容契约

建议新增离线定义：

```ts
type ChallengeDefinition = {
  id: string;
  title: string;
  requiredCapabilityIds: string[];
  evidenceRules: Array<{
    capabilityId: string;
    requiredStepIds: string[];
  }>;
  scenarioIds: string[];
  passEffects: string[];
};
```

挑战内容仍来自已批准题库；在线运行时不调用 AI 生成题目。

## 9. 验收标准

1. 未掌握全部前置的学生仍能开始挑战。
2. 开始前能看见已具备和缺失的能力，但只需一次确认。
3. 只答对最终数值不会误判为挑战通过。
4. 挑战通过后，图谱节点状态由服务端重新计算。
5. 挑战节点只显示未开启、开启、通关三种状态，建议前置不足不产生锁图标或禁用态。
6. 挑战失败后能够返回具体 `diagnosisCode` 和 `focusStepId`。
7. 挑战 session 可恢复，刷新页面不丢失当前数学对象。

## 10. 埋点与指标

- `challenge_node_opened`
- `challenge_started_early`
- `challenge_passed`
- `challenge_failed`
- `challenge_retry_clicked`
- `challenge_remediation_clicked`

核心指标：提前挑战成功率、挑战失败后进入精准补强的比例、补强后重试通过率。
