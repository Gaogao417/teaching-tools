# PRD-03：题图直接操作系统

## 文档状态

- 状态：Draft
- 优先级：P0
- 依赖：现有 `TopicActionContract`、几何点线模型与 runtime 判题
- 可独立上线：是

## 1. 背景与问题

五专题当前已具备 `mark-segments`、`mark-ratio`、`construct-parallel` 和 `equation` 等动作契约，但交互层仍依赖外部槽位表达操作进度。主要摩擦：

- 学生点图后还要去外部槽位确认自己选了什么。
- 线段、数值与对应关系离开题图，增加注意力搬运。
- 作辅助线一次展示多个槽位，学生先理解 UI 顺序，再理解几何动作。
- 误点后容易整步清空，而不是只撤销最近对象。
- 错误反馈停留在操作区，没有指向图上的具体错误对象。

## 2. 产品目标

- 选点、选边、标数、配对应边和作线全部直接发生在题图上。
- 操作结果持续留在数学对象上，进入下一步不消失。
- 一次只暴露一个主要动作。
- 支持局部取消与单步撤销。
- Learn 与 Practice 复用完全相同的直接操作组件。

## 3. 非目标

- 不把页面做成自由几何画板。
- 不允许学生创建契约外的任意点线。
- 不改变服务端正确答案和判题边界。
- 不把所有结构化输入都移除；列式仍可使用语义槽位。

## 4. 通用交互状态

每个可操作对象必须支持：

```text
idle → available → selected → filled → correct
                         └──────→ wrong → selected
```

状态含义：

- `idle`：当前动作不允许操作。
- `available`：当前动作允许点击；鼠标悬停、键盘聚焦或触摸时轻量高亮。
- `selected`：已选中，等待输入或第二个对象。
- `filled`：已经形成数值、对应关系或构造结果。
- `wrong`：仅当前错误对象进入错误态，其他正确状态保留。
- `correct`：结果写入数学对象，并进入下一动作。

## 5. 操作模式

### 5.1 点边标数

流程：

1. 学生直接点击线段。
2. 线段变色、加粗。
3. 数字输入框在该线段中点附近出现并自动聚焦。
4. 输入完成后，输入框收为贴在线段旁的数值标签。
5. 再点一次该线段，只取消这条标注。

要求：

- 透明点击热区最小 44px，不改变可见线宽。
- 移动端数字字段使用合适的 `inputmode`。
- 输入框不得遮挡点名、已知数字或目标边。
- 多条已标边同时保留。

### 5.2 配对应边

流程：

1. 提示“先点第一条边”。
2. 第一条边变色并出现编号 `①`。
3. 提示变为“现在点它的对应边”。
4. 第二条边使用同色和同编号，形成第一组对应。
5. 第二组使用编号 `②` 重复以上过程。

禁止在图外显示四个空槽位。图外只保留一句当前动作和已完成组数。

### 5.3 作平行辅助线

流程必须渐进：

1. 点过线点。
2. 只高亮当前合法的平行参照边。
3. 点参照边后出现虚线预览。
4. 点连接所需的两个外点。
5. 显示连接线与交点预览。
6. 确认后将结果写入原图。

任何时刻只强调下一类合法对象，不同时暴露“点、线、外点 1、外点 2”四个槽位。

### 5.4 共线边互化

用于子母型：

- 学生点选相关共线线段。
- 线段在图上同步高亮。
- 图边缘出现最小关系式，例如 `AC = AD + DC`。
- 学生只输入本步未知值，完成后数值写回相应线段。

该动作不能被合并成普通“标边长”，因为它承担独立诊断意义。

### 5.5 列式

只有列式阶段允许语义槽位：

```text
未知边 = [已知边] × [未知边份数] / [已知边份数]
```

- 当前槽位高亮。
- 点击图上的线段或标签填入当前槽位。
- 点击已填槽位可单独替换。
- 最终结果使用普通输入框。
- 前序图上标注保持可见。

## 6. 全局操作规则

- 主操作：`提交本步`。
- 次操作：`撤销刚才`。
- `清空本步` 放入低频菜单，不与提交同权重。
- 结构未完整时提交按钮不可用，并说明还缺什么；不只显示灰色按钮。
- 正确后短暂确认并自动进入下一步。
- 错误后停留原步骤，不清空正确对象。
- Learn 展示右侧步骤引导；Practice 隐藏完整流程，但操作方式不变。

## 7. 契约调整

现有 `TopicActionPrimitive` 可以保留。建议补充展示层字段：

```ts
type TopicInteractionPresentation = {
  selectionMode?: "single" | "pair" | "ordered";
  inputAnchor?: "segment-midpoint" | "point-offset" | "workspace";
  retainCompletedMarks?: boolean;
  allowLocalUndo?: boolean;
  availableObjectIds?: string[];
  capabilityId?: string;
};
```

前端只根据契约渲染可操作对象，不根据题目文字推断操作顺序。

## 9. 验收标准

1. `mark-segments` 全流程无需外部选择槽位。
2. 点击线段后，输入框出现在该线段附近并自动聚焦。
3. `mark-ratio` 使用图上同色、同号表达两组对应关系。
4. `construct-parallel` 任一时刻只提示一种下一操作对象。
5. 误点可以局部取消或撤销一步，其他正确结果不丢失。
6. 错误反馈能定位到图上的具体点、边或关系。
7. 鼠标、触摸和键盘均可完成主要动作。
8. 现有 topic runtime 后端测试保持通过。

## 10. 体验指标

- 完成“标三条已知边”的视线跨区次数明显下降。
- 非数学错误率：因选错槽位顺序导致的错误趋近于零。
- 清空整步的使用率低于单步撤销。
