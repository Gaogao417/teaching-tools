# 相似专题 UI/UX 改版：PRD 拆分

## 目标

把当前“章节下五个平铺任务”的入口，升级为基于前置能力的学习图谱；同时把专题内的选点、选边、标数、配对应边和作辅助线改为题图上的直接操作，并形成“挑战失败 → 精准补强 → 返回挑战”的闭环。

本轮只覆盖以下五个专题：

- `parallelLineRatios`：平行线比例
- `auxiliaryTwoRatios`：比例辅助线
- `reverseASimilarity`：反 A 形相似
- `nestedSimilarity`：子母型相似
- `butterflySimilarity`：蝶形相似

## 产品任务拆分

| PRD | 产品任务 | 解决的问题 | 主要落点 |
| --- | --- | --- | --- |
| 01 | [相似专题学习图谱](./PRD-01-learning-map.md) | 五个专题平铺、路径关系不清、恢复学习成本高 | 专题入口、节点详情、地图状态 |
| 02 | [能力进度与解锁规则](./PRD-02-progression-unlock.md) | 前置关系没有运行时真值，前端无法解释为何解锁 | 能力状态、解锁计算、进度 API |
| 03 | [题图直接操作系统](./PRD-03-direct-manipulation.md) | 槽位过多、注意力在题图和操作区之间搬运 | 点边标数、配对、作线、局部撤销 |
| 04 | [多前置综合挑战关](./PRD-04-challenge-nodes.md) | 无法允许学生提前证明能力，也无法表达多个前置 | 挑战节点、软门槛、跳关验证 |
| 05 | [失败诊断与补强回路](./PRD-05-remediation-loop.md) | 挑战失败后只能泛化地“回去学习”，无法精准补缺 | 诊断映射、短练习、断点返回 |

## 推荐实施顺序

完整并行/串行开发规划见 [IMPLEMENTATION-PLAN.md](./IMPLEMENTATION-PLAN.md)。

```text
PRD-02 能力进度与解锁
        ↓
PRD-01 学习图谱入口

PRD-03 题图直接操作（可与上面并行开发）
        ↓
PRD-04 综合挑战关
        ↓
PRD-05 失败诊断与补强回路
```

原因：

- 图谱需要 PRD-02 提供节点状态，不能由前端临时猜测。
- PRD-03 可以先改现有五专题 runtime，不依赖图谱上线。
- 挑战关必须能够记录动作级证据，依赖 PRD-03 的结构化操作。
- 补强回路依赖挑战失败诊断与可恢复 session，最后实施风险最低。

## 共同产品原则

1. 图谱是有向能力图，不是把菜单卡片摆成弯曲道路。
2. 学习关卡可以因前置能力锁定；挑战关使用软门槛，始终允许主动尝试。
3. 题图同时承担信息源、操作区和结果区。
4. 槽位只用于具有明确结构语义的列式，不用于普通选点、选边和标数。
5. 错误只影响当前动作，不清空此前正确结果。
6. Learn、Practice、Review 继续使用同一个数学对象和服务端判定真值。

## 明确不在本轮范围

- 通用 LMS 课程图谱编辑器
- 教师端可视化编排工具
- 跨学科通用推荐算法
- AI 在线生成补强题
- 改造 `teaching_skills` 题库生产链
