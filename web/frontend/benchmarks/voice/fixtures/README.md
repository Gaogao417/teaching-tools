# Voice benchmark microphone fixtures

These are the **only** allowed fixtures in the voice benchmark. They are fed to
Chromium via `--use-file-for-fake-audio-capture=<abs path>` (see
`playwright.config.ts`) so recorded-turn and Live Coach specs can run a fixed,
reproducible "microphone" input instead of asking a human to speak live. Nothing
else — `Audio`, `fetch`, the backend cache, ASR, LLM, TTS, or any provider — is
mocked.

## Source and reproducibility

Generated by `generate.sh` on macOS using built-in `say` (voice `Tingting`,
`zh_CN`) + `afconvert` (to 16 kHz mono 16-bit PCM WAV) for speech, and pure
Python (`wave` + a seeded `random`) for silence/noise. Regenerate with:

```bash
cd web/frontend/benchmarks/voice/fixtures && ./generate.sh
```

The transcripts are fixed; the only knobs are `VOICE_BENCHMARK_FIXTURE_VOICE`
(default `Tingting`) and `VOICE_BENCHMARK_FIXTURE_RATE` (default `180`). Different
macOS voice versions can shift durations slightly, so the SHA-256 and measured
duration below are recorded for the run that produced the committed clips.

## Usage in specs

Set `VOICE_BENCHMARK_FAKE_MIC_WAV` to an **absolute** path before launching the
benchmark. Recorded-turn and Live Coach specs self-skip when this is unset. To
swap the active clip per scenario, point the env var at the desired file and
re-run (the launch arg is read once per Playwright process).

```bash
export VOICE_BENCHMARK_FAKE_MIC_WAV="$PWD/web/frontend/benchmarks/voice/fixtures/generated/short.wav"
```

## What these are NOT

- Not real student utterances; ASR transcripts will vary with the provider model.
- Not a substitute for cache/provider behavior; the backend still calls the real
  Qwen ASR / LLM / CosyVoice / realtime providers.
- `silence-2s.wav` and `noise-unrecognizable-2s.wav` exist to exercise the ASR
  and arbitration error/cancellation paths, not to assert a specific transcript.
