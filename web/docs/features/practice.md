# Practice Feature Spec

## 摘要

练习页是整个产品的运行时主页面。

它不是某个题型的实现页，而是 `ExerciseRuntimeHost` 的页面壳层。

## 页面职责

练习页负责：

- 创建和恢复 session
- 挂载教学运行时
- 渲染左侧工作区和右侧引导区
- 调度统一反馈
- 在题目之间推进
- 在完成时展示结果总结层

练习页不负责：

- 生成题目真值
- 判题
- 作为题型专属实现文件长期膨胀

## 页面结构

### 顶部

- 当前任务标题
- 当前题号 / 总题数
- 计时
- 返回与重开入口

### 中部

- 左侧 `WorkspaceScene`
- 右侧 `GuidePanel`

### 底部

- 反馈卡
- 提示区
- 历史 / 轻量趋势信息

## 左右边界

### 左侧工作区

左侧是唯一操作区。

允许出现：

- 可点击边
- 可点击区域
- 输入锚点
- 公式槽
- 当前步骤需要的提交入口

不允许出现：

- 和右侧重复的教学说明堆砌

### 右侧引导区

右侧是任务日志和教师口令面板。

允许出现：

- 当前目标
- step tracker
- 已完成步骤摘要
- 错误提示
- 下一步提示

不允许出现：

- 主输入控件
- 与左侧重复的可提交操作

## 与运行时的关系

练习页消费的是：

- `ExerciseRuntimeSpec`
- `ServerRuntimeState`
- 本地 `ClientDraftState`

练习页向后端上报的是：

- 标准动作事件
- 或兼容层下的题型 answer payload

## 当前三类任务如何落位

### meaning

- 左侧选边
- 右侧提示“先选分子 / 再选分母”

### ratioToSide

- 左侧在边上输入值
- 右侧提示当前目标比值和缺失项

### guidedSolve

- 左侧完成所有步骤输入
- 右侧只读展示步骤推进

这三类任务只是同一运行时模型的实例，不应演化成三套页面结构。

## 验收条件

- 学生不需要在右侧寻找输入入口
- 页面能承接多题型而不让 `PracticePage` 膨胀成巨型分支文件
- 正确、错误、完成时有统一反馈
- session 可恢复
- 完成后能自然进入总结和结果页
