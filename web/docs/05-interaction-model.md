# Interaction Model

## 摘要

整个 Web 版项目的交互模型只有一个核心原则：

左侧负责操作，右侧负责引导。

学生在页面中的所有可提交动作，都应发生在左侧工作区；右侧只负责告诉学生：

- 现在在做什么
- 刚才做对还是做错
- 下一步应该看哪里

这个原则适用于统一学习运行时中的两种产品态：

- `example`
  高提示、强引导、带讲解的例题态
- `exercise`
  更少提示、以短练习组为主的练习态

两者的差别应主要体现在提示强度、反馈口径和组卷逻辑上，而不是页面壳层或工作区对象模型上。

## 全局交互原则

### 1. 单任务焦点

任一时刻，页面只强调一个当前任务。

页面不应同时要求学生：

- 看多个步骤
- 在左右两边来回找输入控件
- 自己判断下一步该去哪

### 2. 技能单元优先

任一题目或题组都应围绕明确的 `skill unit` 组织。

这意味着：

- `example` 要明确它在教哪个主要 `skill unit`
- `exercise` 要明确它在练哪个主要 `skill unit`
- 同一步里不要混测两个彼此独立的方法动作

### 3. 操作与说明分区

左侧工作区负责：

- 点边
- 填值
- 提交当前步骤
- 接收局部反馈

右侧引导区负责：

- 展示当前步骤
- 展示当前题目标
- 展示错误提示
- 展示完成状态
- 展示下一步口令

右侧不应出现：

- 可提交输入框
- 主提交按钮
- 与左侧重复的交互控件

### 4. 即时反馈

每次操作都要有立刻可感知的结果：

- 点中了哪条边
- 当前输入是否有效
- 当前步骤是否完成
- 是否即将自动进入下一题

反馈分为 3 层：

- 局部反馈
  作用于边、输入框、步骤卡。
- 页面反馈
  作用于页面壳层，如 pulse / shake / glow。
- 音效反馈
  对应正确、错误、完成 3 类状态。

### 5. 引导强度按模式变化

`example` 和 `exercise` 共用同一套工作区原则，但右侧引导强度不同。

- `example`
  当前目标更显式，步骤口令更强，允许展示中间步骤摘要和更教学化的修正提示。
- `exercise`
  当前目标更简洁，提示更克制，更强调学生自己完成动作链。

### 6. 引导先于自由编辑

交互默认是“引导式任务流”，不是自由画布。

这意味着：

- 只开放当前步骤需要的操作
- 未到的步骤不允许提前提交
- 错误反馈给“下一步该看什么”，不只给红色报错

## 学习模式

### `example`

目标：

- 教会一个主要 `skill unit`
- 让学生看到完整的方法链
- 在第一次接触时减少无谓猜测

引导特征：

- 当前步骤更清楚
- 右侧提示更具体
- 错误反馈更偏纠偏和教学说明

### `exercise`

目标：

- 检验和巩固已经学过的 `skill unit`
- 根据薄弱点、错题/错步和学生选择组织短练习组
- 用更少提示换取更真实的熟练度信号

引导特征：

- 题干更短
- 右侧提示更克制
- 错误反馈更偏诊断与纠错，而不是完整重讲

## 统一状态机

页面级 session phase 统一为：

- `answering`
- `correct_pause`
- `wrong_feedback`
- `group_finished`

解释如下：

- `answering`
  当前题或当前步骤可操作。
- `correct_pause`
  当前动作正确，短暂停顿，准备自动流转。
- `wrong_feedback`
  当前动作错误，停留在原题并显示修正提示。
- `group_finished`
  本组完成，进入完成反馈和结果流。

页面不应额外发明与上述 phase 并行的第二套主状态机。

产品侧的 `example` / `exercise` 是学习模式，不是另一套页面级 phase。二者应共享这套运行时 phase。

## 工作区模型

左侧工作区是统一的“教学操作面”。

其可交互元素只有两类：

- 命中层
  例如边、点、目标区域、投放区。
- 输入层
  例如边上输入框、步骤输入框、最终分式输入。

其余元素默认是只读装饰：

- 背景网格
- 标签
- 顶点名
- 角色说明
- 视觉高亮底板

`exercise` 不应因为提示更少，就引入与 `example` 完全不同的工作区对象模型。通常应减少 guide 负担，而不是换工作对象。

工作区必须满足：

- 命中区足够大，尤其是斜边和移动端
- 命中反馈立即可见
- 输入锚点稳定，不在步骤切换时大幅跳动

## 引导区模型

右侧引导区不是第二个工作区，而是“教师口令面板”。

必须包含：

- 当前题目标
- 当前步骤
- 步骤完成状态
- 错误后的修正提示
- 正确后的下一步提示

可选包含：

- 轻量公式展示
- 当前题摘要
- 当前题或当前练习组进度状态

不应包含：

- 边点击控件
- 数值输入框
- 与左侧重复的提交入口

## 反馈节奏

### `example` 中的正确

- 局部元素高亮
- 页面出现正确反馈
- 播放正确音效
- 如当前题已完成，则短暂停顿后自动进入下一题

### `example` 中的错误

- 局部错误态可见
- 页面出现错误反馈
- 播放错误音效
- 停留原题，并把提示聚焦到“该检查什么”

### `exercise` 中的正确与错误

- 仍然保留一致的局部、页面和音效反馈
- 正确提示比 `example` 更简洁
- 错误提示应指出错误点，但不默认重讲整条方法链

### 整组完成

- 页面出现完成反馈
- 播放完成音效
- 弹出成绩层
- 允许进入结果页、下一轮 `example` 或新的 `exercise`

## 验收规则

- 学生不需要在右侧寻找输入入口。
- 任一学习模式都能明确区分“操作区”和“引导区”。
- `example` 与 `exercise` 的差别主要体现在提示强度和反馈口径，而不是页面骨架。
- `exercise` 能以短练习组的形式存在，而不是被迫写成无限题流。
- 正确、错误、完成都有一致的视觉和音效反馈。
- 内容差异只体现在左侧操作内容和右侧文案，不改变全局交互原则。
- 新增题型时，先适配这套交互模型，再决定局部变体。
