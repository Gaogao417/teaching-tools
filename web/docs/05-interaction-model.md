# Interaction Model

## 摘要

整个 Web 版项目的交互模型只有一个核心原则：

左侧负责操作，右侧负责引导。

学生在页面中的所有可提交动作，都应发生在左侧工作区；右侧只负责告诉学生：

- 现在在做什么
- 刚才做对还是做错
- 下一步应该看哪里

这个原则适用于首页之外的所有训练型页面，尤其是练习页。

## 全局交互原则

### 1. 单任务焦点

任一时刻，页面只强调一个当前任务。

页面不应同时要求学生：

- 看多个步骤
- 在左右两边来回找输入控件
- 自己判断下一步该去哪

### 2. 操作与说明分区

左侧工作区负责：

- 点边
- 填值
- 提交当前步骤
- 接收局部反馈

右侧引导区负责：

- 展示当前步骤
- 展示当前题目标
- 展示错误提示
- 展示完成状态
- 展示下一步口令

右侧不应出现：

- 可提交输入框
- 主提交按钮
- 与左侧重复的交互控件

### 3. 即时反馈

每次操作都要有立刻可感知的结果：

- 点中了哪条边
- 当前输入是否有效
- 当前步骤是否完成
- 是否即将自动进入下一题

反馈分为 3 层：

- 局部反馈
  作用于边、输入框、步骤卡。
- 页面反馈
  作用于页面壳层，如 pulse / shake / glow。
- 音效反馈
  对应正确、错误、完成 3 类状态。

### 4. 引导先于自由编辑

交互默认是“引导式任务流”，不是自由画布。

这意味着：

- 只开放当前步骤需要的操作
- 未到的步骤不允许提前提交
- 错误反馈给“下一步该看什么”，不只给红色报错

## 统一状态机

页面级 session phase 统一为：

- `answering`
- `correct_pause`
- `wrong_feedback`
- `group_finished`

解释如下：

- `answering`
  当前题或当前步骤可操作。
- `correct_pause`
  当前动作正确，短暂停顿，准备自动流转。
- `wrong_feedback`
  当前动作错误，停留在原题并显示修正提示。
- `group_finished`
  本组完成，进入完成反馈和结果流。

页面不应额外发明与上述 phase 并行的第二套主状态机。

## 工作区模型

左侧工作区是统一的“教学操作面”。

其可交互元素只有两类：

- 命中层
  例如边、点、目标区域、投放区。
- 输入层
  例如边上输入框、步骤输入框、最终分式输入。

其余元素默认是只读装饰：

- 背景网格
- 标签
- 顶点名
- 角色说明
- 视觉高亮底板

工作区必须满足：

- 命中区足够大，尤其是斜边和移动端
- 命中反馈立即可见
- 输入锚点稳定，不在步骤切换时大幅跳动

## 引导区模型

右侧引导区不是第二个工作区，而是“教师口令面板”。

必须包含：

- 当前题目标
- 当前步骤
- 步骤完成状态
- 错误后的修正提示
- 正确后的下一步提示

可选包含：

- 轻量公式展示
- 当前题摘要
- 本题进度状态

不应包含：

- 边点击控件
- 数值输入框
- 与左侧重复的提交入口

## 三类题型的交互模式

### Group 1: meaning

目标：

- 建立“分子边 / 分母边”的有序选择感

交互：

- 左侧点击边
- 第一次点击填充分子槽
- 第二次点击填充分母槽
- 正误判断后立即反馈

右侧引导：

- 当前是“先选分子”还是“再选分母”
- 错误时提醒先看参考角，再判断对边、邻边、斜边

### Group 2: ratioToSide

目标：

- 把题目中的比值真正映射到三条边上

交互：

- 左侧边上输入值
- 输入焦点按当前未完成边推进
- 提交动作在左侧发生

右侧引导：

- 当前题的三角比目标
- 当前还缺哪条边
- 错误时提醒“先确定参考角，再把比值对应回三条边”

### Group 3: guidedSolve

目标：

- 形成稳定的分步解题动作链

交互：

- 所有步骤输入都在左侧工作区完成
- 当前 step 完成后左侧解锁下一步需要的输入
- 最终分式输入也属于左侧

右侧引导：

- 只读 stepper
- 当前步骤口令
- 已完成步骤摘要
- 下一步提示

## 反馈节奏

### 正确

- 局部元素高亮
- 页面出现正确反馈
- 播放正确音效
- 如当前题已完成，则短暂停顿后自动进入下一题

### 错误

- 局部错误态可见
- 页面出现错误反馈
- 播放错误音效
- 停留原题，并把提示聚焦到“该检查什么”

### 整组完成

- 页面出现完成反馈
- 播放完成音效
- 弹出成绩层
- 允许进入结果页或再次练习

## 验收规则

- 学生不需要在右侧寻找输入入口。
- 任一题型都能明确区分“操作区”和“引导区”。
- 正确、错误、完成都有一致的视觉和音效反馈。
- 题型差异只体现在左侧操作内容和右侧文案，不改变全局交互原则。
- 新增题型时，先适配这套交互模型，再决定局部变体。
