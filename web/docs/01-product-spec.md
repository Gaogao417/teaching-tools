# Product Spec

## 摘要

这个项目不是一个普通的刷题网页，而是一个“教学任务驱动的学习应用”。

它的目标不是把答案收上来，而是把学生一步一步带到正确的数学动作链上，并据此安排后续练习量与辅助。

产品核心学习运行时由两种互补状态组成：

- `example`
  高提示、强引导、带讲解的例题完成态，用来教会方法。
- `exercise`
  更少提示、以短练习组为主的训练态，用来检验、巩固和补弱。

这两种状态都围绕同一个底层概念组织：`skill unit`。

## 目标用户

主要用户有两类：

- 学生
  通过浏览器进入页面，先在 `example` 中学习方法，再在 `exercise` 中巩固和检验。
- 老师
  关心 `skill unit` 的组织方式、学习结果、教学一致性和后续可扩展性。

当前首版先服务学生单人练习，不引入账号体系。

## 核心概念

- `skill unit`
  可跨题复用的方法步骤单元，例如“单位圆找角”“范围变换”“范围内筛角”“回代求解”。它是诊断、补练和内容组织的最小教学单位。
- `example`
  围绕一个主要 `skill unit` 展开的高提示例题。它负责讲解、示范和首轮掌握。
- `exercise`
  围绕一个或少数几个 `skill unit` 展开的低提示短练习组。它负责检验、巩固、补弱和练习量定制。
- `learning runtime`
  学生进入工作区后的统一学习壳层。`example` 与 `exercise` 是其中两种产品态，不应被写成两套完全独立的页面产品。

## 产品目标

### 1. 教学目标

- 帮学生建立稳定的 `skill unit` 和动作链，而不是只记最终答案
- 让学生不是只记结果，而是在场景中完成识别、赋值、组合、推导
- 让 `example` 负责教会方法，让 `exercise` 负责检验与巩固
- 让“当前该做什么”始终清晰

### 2. 系统目标

- 让新题型可以落在同一套教学运行时内，而不是复制页面
- 让前端和后端职责清晰
- 让题目规则和前端表现分离
- 让 `exercise` 能根据平时生疏点、错题/错步和学生选择组织短练习组

## 核心产品原则

- 学习运行时是主战场，首页只是入口
- `skill unit` 是最小教学组织单位
- 默认先 `example`，再 `exercise`
- 左侧负责操作，右侧负责引导
- 一次只强调一个当前任务
- 正误必须有即时反馈
- 正确后默认自动推进
- 题型增长不能依赖复制页面实现

## 核心用户流程

### 1. 进入任务

- 学生进入首页
- 填写姓名
- 选择任务
- 进入学习运行时

### 2. 完成 `example`

- 系统展示当前例题目标
- 学生在左侧工作区执行动作
- 右侧持续给出步骤和提示
- 系统返回正确 / 错误 / 继续推进反馈
- 系统记录学生在哪些 `skill unit` 上仍不稳定

### 3. 进入 `exercise`

- 系统根据平时生疏点、错题/错步和学生选择组织一组短练习
- `exercise` 提示少于 `example`，但仍使用同一学习运行时
- 学生完成练习组后看到结果与下一步建议

### 4. 完成一个学习循环

- 学生可以查看结果页
- 学生可以进入下一组 `example`
- 学生可以继续做围绕特定 `skill unit` 的 `exercise`

## 产品范围

当前版本必须覆盖：

- 任务首页
- 统一学习运行时，能够承载 `example` 与 `exercise`
- 结果页
- 独立后端 session 与结果持久化
- 围绕 `skill unit` 组织内容
- 能够基于薄弱点、错题/错步和学生选择生成短练习组

当前版本不要求：

- 登录体系
- 教师后台
- 可视化编题器
- 多人同时协作
- 无限题流式自适应刷题

## 成功标准

- 学生在 `example` 中不需要猜测下一步
- 学生在 `exercise` 中能感受到提示减少，但仍不需要在页面上寻找输入位置
- 正误反馈明确且即时
- 生疏 `skill unit` 会真实影响后续 `exercise` 的练习内容
- 一个学习循环自然闭环，不需要手动拼接多个页面
- 新题型可以通过通用运行时接入，而不是再发明新页面

## 非目标

- 不追求通用 LMS 平台
- 不把首版做成自由探索型几何软件
- 不把产品做成纯题海刷题器
- 不为了灵活而让前端变成后端远程控制的模板系统

## 文档边界

本文件只定义产品目标和范围，不定义：

- 组件结构
- API 字段
- 页面内部状态变量

本文件使用的正式产品术语是 `skill unit`、`example`、`exercise`。
如果其他实现文档或代码里仍出现 `practice`，应视为当前实现名，而不是首选产品名。
