# Product Spec

## 摘要

这个项目不是一个普通的刷题网页，而是一个“教学任务驱动的练习应用”。

它的目标不是把答案收上来，而是把学生一步一步带到正确的数学动作链上。

产品核心体验应接近一个教学小游戏：

- 学生进入任务
- 系统给出明确当前目标
- 学生在工作区完成动作
- 系统立即反馈
- 当前步骤推进
- 一组任务完成后总结成绩

## 目标用户

主要用户有两类：

- 学生
  通过浏览器进入页面，按引导完成练习。
- 老师
  关心任务组织方式、训练结果、教学一致性和后续可扩展性。

当前首版先服务学生单人练习，不引入账号体系。

## 产品目标

### 1. 教学目标

- 帮学生建立稳定的三角比概念和动作链
- 让学生不是只记结果，而是在场景中完成识别、赋值、组合、推导
- 让“当前该做什么”始终清晰

### 2. 系统目标

- 让新题型可以落在同一套教学运行时内
- 让前端和后端职责清晰
- 让题目规则和前端表现分离

## 核心产品原则

- 练习页是主战场，首页只是入口
- 左侧负责操作，右侧负责引导
- 一次只强调一个当前任务
- 正误必须有即时反馈
- 正确后默认自动推进
- 题型增长不能依赖复制页面实现

## 核心用户流程

### 1. 进入任务

- 学生进入首页
- 填写姓名
- 选择任务
- 进入练习页

### 2. 执行练习

- 系统展示当前题目标
- 学生在左侧工作区执行动作
- 右侧持续给出步骤和提示
- 系统返回正确 / 错误 / 继续推进反馈

### 3. 完成一组

- 最后一题完成后出现总结层
- 学生可以查看结果页或继续新一组

## 产品范围

当前版本必须覆盖：

- 任务首页
- 练习页
- 结果页
- 独立后端 session 与结果持久化
- 三角形场景下的多题型练习

当前版本不要求：

- 登录体系
- 教师后台
- 可视化编题器
- 多人同时协作

## 成功标准

- 学生不需要猜测下一步
- 学生不需要在页面上寻找输入位置
- 正误反馈明确且即时
- 一组流程自然闭环，不需要手动拼接多个页面
- 新题型可以通过通用运行时接入，而不是再发明新页面

## 非目标

- 不追求通用 LMS 平台
- 不把首版做成自由探索型几何软件
- 不为了灵活而让前端变成后端远程控制的模板系统

## 文档边界

本文件只定义产品目标和范围，不定义：

- 组件结构
- API 字段
- 页面内部状态变量
